# 第11至16周闭环工作总清单

整理日期：2026-09-30。本文是工作清单，不是完成报告，也不改变任何 Gate。
依据为第11至16周原始任务、后续范围变更和仓库最近已保存的验证报告。
本次没有重新运行测试、调用询价或审核模型，也没有部署应用。

## 1. 闭环口径

- 不再要求逐条真人审核。采用确定性预检、最高阶模型主审、独立对抗复审、分歧仲裁、受控回写的审核链。
- 历史真人审核保留真实来源，不能改写成模型审核；模型审核不能伪称真人签字。
- 模型不能补造缺失的官方事实、价格、地区可用性或真实试点反馈。
- “通过开发准入 Gate”“本周功能交付完成”“允许客户输出”“真实生产部署”是不同结论，必须分别验收。
- 拒绝、隔离、过期、被新版本替代和有条件批准都是合法处置；闭环不是把所有记录改成 approved。
- 有条件批准必须限定对象、事实、市场、Region、有效期和使用场景；不能扩大成 SKU、性能、SLA 或价格等价。
- 第16周真实用户参与和业务反馈已由项目所有者延期。技术准备可以独立完成，不能因此宣称原始真实试点已经通过。
- 当前根目录 `AGENTS.md` 仍写着 Week1 限定。后续实施前应将阶段范围与已授权的后续任务明确对齐，保留 evidence-first 约束；本清单不修改该文件，也不开始后续业务开发。

## 3. 执行顺序

1. 固定交付范围、数据库和版本基线，处理规则冲突及审核/输出策略。
2. 先执行第14周允许提前进行的审核迁移与根因修复，补齐价格，完成TCO和Decision。
3. 通过第11周准入，再交付销售输出并完成本周验收。
4. 完成第12周市场隔离的全链路验证。
5. 通过第13周准入，交付Streamlit业务工作台。
6. 完成第14周全链路评测。不要把前面的审核迁移模式误当作整周完成。
7. 完成第15周发布候选、恢复与回滚演练。
8. 完成第16周技术准备演练，保留真实试点延期状态。
9. 将来有参与者和业务场景后，恢复第16周真实试点和退出验收。

此顺序避免“第11周等模型审核、第14周又等第13周”的循环依赖。
